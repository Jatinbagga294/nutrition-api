# Deploying to AWS

This puts the API on AWS: a server running the Docker image, a private managed
Postgres database, secrets in Parameter Store, and a billing alarm. All of it is
defined in code in this folder, so it can be created and deleted with one
command each.

```
internet ──80──▶ EC2 (Docker, the API) ──5432──▶ RDS PostgreSQL (private)
                    │
                    └── reads two secrets from SSM Parameter Store via an IAM role
```

**What has been checked and what has not.** Terraform validates the code and the
boot script renders and passes a shell syntax check. It has not been applied to
a real AWS account, because that needs your account. Expect to read one or two
log lines if something is off, and see Troubleshooting below.

## What it costs

Real money can be involved, so read this before you run anything.

- Roughly **$25 a month** if left running outside any free offer: about $8 for
  the server, $13 for the database, a few dollars for storage.
- AWS changed its free tier in 2025. New accounts now get a credit balance
  instead of the older 12 months of free usage. Look at **Billing > Free Tier**
  in your account to see what you actually have.
- A budget alarm is created for you. It emails when spend passes 80% of
  `monthly_budget_usd` (default $5).
- **When you are done, run `terraform destroy`.** A deployment you forgot about
  is the most common way a student AWS bill happens.

## One-time setup

1. **Create an AWS account** at aws.amazon.com and turn on MFA for the root user.
2. **Create a working user.** IAM > Users > Create user, attach the
   `AdministratorAccess` policy for this exercise, and create an access key
   under Security credentials. Delete that key when you finish. (Least-privilege
   policies are the right answer for a real team; for a personal sandbox, admin
   plus a short-lived key is the common trade-off.)
3. **Install the tools:**
   ```
   winget install Amazon.AWSCLI
   winget install Hashicorp.Terraform
   ```
   Open a new terminal, then run `aws configure` and enter the key, its secret,
   region `ca-central-1`, and output format `json`.
4. Check it works: `aws sts get-caller-identity` should print your account.

## Deploy

```
cd deploy/aws
copy terraform.tfvars.example terraform.tfvars      # then put your email in it
terraform init
terraform plan
terraform apply
```

`plan` lists every resource before anything is created. Read it. `apply` asks
you to type `yes`. The database takes about 8 minutes; the server then boots and
builds the image, about 5 more.

## Check it

`terraform apply` prints outputs. Wait a few minutes, then:

```
curl http://<the address in api_url>/health
```

You should get `{"status":"ok"}`. Open `http://<address>/docs` for the
interactive API documentation and create an account through it.

## Try it end to end

1. `POST /auth/signup` with an email and a password of 8 or more characters.
2. `POST /auth/login`, copy the `access_token`.
3. Click Authorize in `/docs`, paste the token, then `POST /entries`.

## Limitations, stated plainly

- **No HTTPS.** The API answers on plain HTTP. A browser blocks an HTTPS site
  (your Vercel app) from calling an HTTP API, so this deployment is for testing
  through `/docs` and `curl`, not for the live app yet. The fix is a CloudFront
  distribution or a load balancer with a certificate in front of it.
- **One server, one database, no failover.** Fine for learning, not for
  customers.
- **The image is built on the server at boot.** A real pipeline builds once in CI,
  pushes to ECR and pulls the image.
- **Tables are created from the models at start.** There is no migration tool
  yet, so changing a column needs Alembic first.

## Tear it all down

```
terraform destroy
```

Type `yes`. Then check the Billing page the next day to confirm it reads $0.

## Troubleshooting

- **`/health` does not answer after 15 minutes.** Get a shell with the
  `shell_command` output, then run `sudo tail -100 /var/log/nutrition-bootstrap.log`.
  It shows exactly which step failed.
- **`aws ssm start-session` says the plugin is missing.** Install the Session
  Manager plugin from the AWS docs, or read the log through the EC2 console
  (Actions > Monitor and troubleshoot > Get system log).
- **`terraform apply` fails on the budget.** The account needs billing access
  for IAM users turned on under Account settings, or delete the
  `aws_budgets_budget` block and set a budget in the console instead.

## Why it is built this way

These are the decisions worth being able to explain.

- **Secrets in Parameter Store, not in the script.** The password is generated by
  Terraform, stored encrypted, and fetched at boot by the server's IAM role. It
  is never in the user data, which anyone with read access to the instance
  could otherwise see.
- **The database has no public address.** Its security group only accepts
  connections from the API server's security group.
- **No SSH port.** Session Manager gives a shell over IAM, so there are no keys
  to lose and no port 22 for scanners to find.
- **IMDSv2 required.** It blocks a request-forgery bug in the app from reading
  the server's credentials.
- **The app refuses to start in production with the default JWT secret.** A
  forgotten variable stops the deploy instead of quietly signing tokens with a
  value that is public in the repository.
- **The default VPC and no NAT gateway.** A NAT gateway costs about $35 a month
  before it carries a byte, and this project does not need one.
- **A billing alarm as code.** So the cost control survives a rebuild.
